# Корректность разбора: решение, а не результат (фиксы 1, 2, 4)

**Дата:** 2026-10-05
**Статус:** реализовано (TDD, 225 тестов зелёные)

## Контекст

Код-ревью вскрыло, что пайплайн разбора нарушает ядро-обещание проекта
(«судим РЕШЕНИЕ по тому, что игрок МОГ знать, а не по ИСХОДУ») в трёх местах.
Эти три фикса восстанавливают принцип до добавления новых параметров (экономика/
итемы/карта — отдельная фаза, ложится поверх чистой базы).

## Фикс 1 — просадка нетворса ≠ автоматическая ошибка

**Было:** `scoring.py` безусловно клеймил `NETWORTH_SWING` как `MISTAKE/HIGH` —
измеримый плохой результат объявлялся плохим решением, без проверки цели/
пространства/альтернатив. Вердикт ехал в `select_deep` → просадка могла попасть
в глубокий разбор как ошибка.

**Стало:** `NETWORTH_SWING → NOT_ENOUGH_INFO / LOW` (симметрично слитой драке).
Остаётся сигналом-маркером времени для ручного разбора, но не обвинением.

## Фикс 2 — структурное разделение «решение / последствие»

**Было:** `render_grounding` передавал в промпт `enemies_near` — ground-truth о
реально находившихся рядом врагах, включая СКРЫТЫХ. Это хиндсайт: информация,
недоступная игроку в точке решения, влияла на оценку его решения. Защитой была
лишь текстовая пометка «мог не знать» — просьба, а не гарантия.

**Стало:** `render_grounding` заменён на `render_knowable` — рендерит ТОЛЬКО
знаемое игроком (вижн, видимые враги, список невидимых с «пропал Nс», свои
ресурсы/позиция/союзники). `enemies_near` в текст оценки НЕ попадает — анти-хиндсайт
теперь на уровне данных. Оба пути оценки (короткий комментарий `episode_note`,
глубокий разбор `moment_coach`) переведены на `render_knowable`; системный промпт
комментария переписан (нет инструкции «используй блок ФАКТ ДЛЯ КОНТЕКСТА»).
`enemies_near` остаётся на `InfoState` — доступен для будущего отображения
последствия и для работы по параметрам, но не как вход решения.

Структурный тест: `render_knowable` двух `InfoState`, различающихся только
`enemies_near`, идентичен.

## Фикс 3 — точка решения вместо момента смерти

**Было:** для смерти карточка и комментарий грунтились на `info_state_at(ev.game_time)` —
момент смерти (HP=0, уже мёртв), бесполезный для оценки решения. А отбор острых
эпизодов (`_severity`) смотрел на `ev.game_time − 5` — другой, произвольный момент.
Отбор и разбор расходились.

**Стало:** у `Episode` появилось поле `decision_time`, считается один раз
`_decision_time(parsed, my_slot, ev)`: для смерти — последняя секунда перед финальным
спадом HP, где `hp_frac ≥ 0.85` (момент, когда ты был ещё в безопасности и выбрал
заход; альтернатива «не идти / TP» ещё существовала); фолбэк — точка макс-HP в окне
30с; для прочих событий — время самого события. `_severity`, `build_card` и оба
LLM-пути грунтятся на `decision_time`. Таймстамп карточки/видеоклип остаются на
`ev.game_time` (смерть — где картинка), но РАЗБОР рассуждает о точке решения.

## Затронутые модули

`scoring.py`, `coach/info_state.py`, `coach/episode_note.py`, `coach/moment_coach.py`,
`episodes.py`, `coach/episode_card.py`. Новых подсистем нет.

## Не входит (следующие фазы)

- Параметры: экономика/темп, итемы/ресурсы, карта/объективы (из уже скачанного
  OpenDota) через то же разделение «решение/последствие».
- Достоверность вижна (день/ночь, деревья, рельеф) — фиделити-фаза.
- Богатый replay-слой (инвентарь/кулдауны/касты) — требует репарса.
- Бенчмарки похожих ситуаций вместо перцентилей — фаза хай-ммр реплеев.
