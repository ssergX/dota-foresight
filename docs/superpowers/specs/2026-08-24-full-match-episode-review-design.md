# Dota Coach — обзор всего матча по эпизодам + видеоклипы — дизайн

> Дата: 2026-08-24. Фича поверх Ф0 (разбор одного матча) и Ф1 (парсинг реплея),
> ветка `feat/full-match-episode-review` от `feat/replay-parse`.
> Предыдущие дизайны: `2026-08-20-single-match-focus-coach-design.md`,
> `2026-08-21-replay-parse-phase1-design.md`.

## Цель

Живой прогон Варианта B (2026-08-24, матч 8961642706, Lina) выявил два запроса
пользователя:

1. **Статичного скрина мало** — «по скрину сложно вспомнить контекст», нужна
   **нарезка ~30с** вокруг эпизода.
2. **Один фокус-момент — мало** — «прога должна все эпизоды разбирать всей карты».

Пункт 2 сознательно разворачивает решение №1 дизайна Ф0 («один фокус-момент вглубь,
не проход по топ-N»). Живой прогон показал, что для ретро-разбора своих игр нужен
**обзор всего матча**, а глубина фокуса остаётся как надстройка на 1–2 острых эпизода.

Итог: `analyze --coach` (при наличии реплея+видео) выдаёт **папку-отчёт по всему
матчу** — на каждый эпизод карточка-факты + видеоклип 30с; на 1–2 самых острых —
полный LLM-разбор (как сейчас).

## Наследуемые принципы (НЕ нарушать)

1. **Анти-результатничество.** Исход матча (`radiant_win`/счёт/слова победа-поражение)
   НЕ передаётся в LLM ни в каком виде. Карточки строит КОД из фактов реплея (исхода
   там нет). Глубокий разбор — по-прежнему **отдельный вызов LLM на эпизод**: модель не
   видит дугу матча (все размены подряд) и не может вывести исход. Сканер-тест
   расширяется на карточки и на промпты глубоких разборов.
2. **Детерминированное ядро.** Список эпизодов, их идентичность (время/тип/вердикт),
   выбор 1–2 глубоких и окна клипов ставит КОД. LLM только формулирует текст глубокого
   разбора. Двойной прогон на тех же входных данных → тот же отчёт (кроме LLM-текста,
   кешируемого по хешу).
3. **Заземление.** Глубокий разбор опирается на курируемый `moment_principles.md`.
4. **Уважение к тонкости данных.** Карточка — это ФАКТЫ (что видел / кто тёмный и
   сколько, ресурсы), а не приговор. Глубокий разбор — гипотеза + вопрос-к-себе +
   чеклист. `not_enough_info` разбирается явно, без обвинений.
5. **Чистые функции отдельно от сетевой/LLM/ffmpeg-склейки.** Логику отбора эпизодов,
   дедупа, окон клипов, чтения часов покрываем юнитами с фейками; ffmpeg/cv2/сеть —
   тонкая склейка.

## Принятые решения (из брейншторма)

| # | Решение |
|---|---|
| 1 | Глубина: короткая карточка на КАЖДЫЙ эпизод + полный LLM-разбор на 1–2 острых |
| 2 | Эпизод = где было решение: **драки** + **каждая твоя смерть** (в т.ч. соло, из реплея) + **просадки нетворса**. Дедуп: смерть внутри окна драки не задваивается |
| 3 | Формат доставки: **папка-отчёт** — `index.html` + `clips/` (H.264 720p, ~5 МБ/клип) |
| 4 | Окно клипа: **20с до + 10с после** события |
| 5 | Карточки пишет **КОД** из реплея (факты); LLM — только 1–2 глубоких → анти-результат цел |
| 6 | Видео **авто-собирается** из записи Steam: найти сессию по match_id, сшить окно, авто-выравнять 0:00 |
| 7 | Авто-выравнивание 0:00 — **матчинг шаблонов цифр** HUD-часов (cv2, без новых зависимостей); сид от `start_time` сужает окно поиска |

## Архитектура

Поток данных:

```
match_id
  ├─ OpenDota: fetch_match → Match (teamfights, objectives, start_time)
  └─ реплей:   parse_replay(match_id) → ParsedReplay (позиции@1Гц, alive, варды)
        │
        ▼
  episodes.build_episodes(match, parsed, account_id) → list[Episode]     ← КОД
    · драки (из extract_events)  · соло-смерти (скан alive→dead по слоту)  · просадки нетворса
    · дедуп смертей внутри окон драк      · severity/verdict — КОД
        │
        ├─ на каждый: episode_card.build_card(episode, parsed) → EpisodeCard  ← КОД (info_state_at)
        ├─ deep-pick: select_deep(episodes, n=1..2) → list[Episode]           ← КОД (ранг по verdict/severity)
        │     └─ на выбранные: explain_moment(...) → MomentBrief              ← LLM (отдельный вызов/эпизод)
        │
        └─ видео (опционально, мягкая деградация):
             steam_recording.find_session(match_id) → (session_dir, avail_epoch)
             steam_recording.stitch_window(session_dir, rec_start, rec_end) → match.mp4
             align.auto_offset(match.mp4, coarse_seed) → offset               ← шаблоны цифр
             на каждый эпизод: clip.extract(match.mp4, t, offset) → clips/NN.mp4  ← H.264 720p
        ▼
  report.render_match_report(episodes, clips_dir, out_dir)  → index.html + clips/
```

Правило существующего кода не ломаем: `extract_events`, `score_events`,
`select_focus_moment`, `explain_moment`, `info_state_at`, `parse_replay`,
`render_report`/`_moment_brief_section` переиспользуются; одиночный разбор Ф0 остаётся
рабочим для матчей без реплея.

## Компоненты

Новые модули — одна ответственность на файл.

### `episodes.py` — сбор списка эпизодов (КОД, без сети/LLM)

```python
@dataclass
class Episode:
    moment: ScoredMoment       # источник: событие + score/verdict/reasons (для драк/просадок — из
                               #   score_events; для смертей — сконструирован кодом). Несёт game_time,
                               #   kind (event.type), summary, data. deep-pick и explain_scored работают
                               #   ровно с этим полем — тип-мост к существующей LLM-инфре.
    severity: float            # для deep-pick, детерминированная (может усиливать score момента)

def build_episodes(match, parsed, account_id) -> list[Episode]
def my_death_times(parsed, my_slot) -> list[int]   # скан alive→dead по слоту (соло тоже)
```

Каждый `Episode` оборачивает `ScoredMoment` — единый тип-мост: `episode_card`,
`select_deep` и `explain_scored` берут `episode.moment`, никакой конвертации Episode↔
ScoredMoment по месту. Для смертей `ScoredMoment` конструирует КОД (EventCandidate типа
`DEATH` + вердикт/severity), для драк/просадок — берётся готовый из `score_events`.

- **Драки и просадки** — из `extract_events` (фильтр по `EventType.TEAMFIGHT`,
  `NETWORTH_SWING`), вердикт/severity — из существующего `score_events`.
- **Смерти** — `my_death_times(parsed, my_slot)`: скан `parsed.frames` по моему слоту,
  ловим переход `alive → not alive` (респавн `dead→alive` игнор). Даёт ВСЕ смерти,
  включая соло вне драк — то, чего нет в OpenDota-объекте игрока (там только суммарный
  `deaths`). Смерть с `t` внутри `[tf.start-δ, tf.end+δ]` любой драки **сворачивается в
  ту драку** (не отдельный эпизод); δ≈10с.
- **Severity смерти** (КОД, детерминированно): базовая + бонус за «зашёл вслепую»
  (много `unseen_enemies` при высоком HP% из `info_state_at`) — острые смерти всплывают
  в deep-pick. Вердикт смерти — `neutral` по умолчанию (данные не осуждают факт смерти),
  `not_enough_info` если реплей-кадра/инфо-состояния на `t` нет.
- Сортировка результата по `game_time`.

### `coach/episode_card.py` — карточка-факты (КОД, без LLM)

```python
@dataclass(frozen=True)
class EpisodeCard:
    game_time: int
    verdict: Verdict
    facts: str          # человекочитаемо: что видел/кто тёмный/ресурсы (render_info_state)
    numbers: dict       # числа эпизода (deaths, gold_delta, unseen_enemies, ...)
    info: InfoState | None

def build_card(episode, parsed, my_slot) -> EpisodeCard
```

Переиспуз `info_state_at` + `render_info_state`. Если реплей-инфо нет — `facts` из
`episode.data` (числа OpenDota), без вижн-блока. Исхода нет by construction.

### deep-pick — выбор 1–2 глубоких (КОД, в `moment_focus.py`)

```python
def select_deep(episodes: list[Episode], n: int = 1) -> list[Episode]
```

Ранжирование как в `select_focus_moment` (вердикт `mistake` → `neutral` →
`not_enough_info`, затем `-severity`, затем `game_time`), берём первые `n`. Дефолт
`n=1`; флаг CLI `--deep N` (кап 2, чтоб не разориться на LLM и не растянуть отчёт).
Глубокий разбор каждого — существующий `explain_moment` (отдельный вызов на эпизод;
для этого `explain_moment`/`build_moment_prompt` принимают конкретный эпизод, а не
только `select_focus_moment(moments)` — минимальный рефактор: выделить
`explain_scored(moment, llm, info_state)`).

### `video/steam_recording.py` — локатор + сшивка записи (склейка)

```python
def find_session(match, gamerecordings_dir) -> tuple[str, int] | None   # (session_dir, avail_epoch_msk)
def stitch_window(session_dir, avail_epoch, rec_start_s, rec_end_s, out_mp4, ffmpeg) -> None
```

- **find_session**: скан `bg_570_*`, читаем `availabilityStartTime` из `session.mpd`;
  окно матча в wall-clock = `[start_time, start_time+duration]` (эпохи); выбираем
  сессию, чей ретейн-интервал `[avail + (min_chunk-1)*3, avail + max_chunk*3]` его
  покрывает. Мягкая деградация: нет покрывающей сессии → `None` (клипов не будет, отчёт
  по данным всё равно рендерим).
- **stitch_window**: бинарный concat `init-stream0.m4s` + чанки диапазона (по номеру
  из rec-секунд) → `ffmpeg -c copy -movflags +faststart` → seekable HEVC mp4. Режем
  только окно матча (не весь буфер). ffmpeg — `imageio_ffmpeg.get_ffmpeg_exe()`.

### `video/align.py` — авто-выравнивание 0:00 (шаблоны цифр)

```python
def read_clock(frame_bgr, templates, box) -> int | None          # MM:SS → секунды, матч шаблонов
def auto_offset(video, templates, box, coarse_seed, ffmpeg) -> float | None
```

- Шрифт HUD-часов и позиция фиксированы на 1920×1080 → 10 шаблонов цифр `0–9`
  собраны ОДИН раз из калиброванных кадров матча 8961642706 (0:00@183с, 10:00@933с) и
  лежат ассетами `assets/clock_digits/{0..9}.png` + `assets/clock_box.json` (координаты
  области MM:SS). `read_clock` вырезает область, бьёт на позиции цифр, каждую — по
  максимуму нормированной кросс-корреляции (`cv2.matchTemplate`).
- **auto_offset**: сид = `start_time − avail_epoch` (грубо, может врать на минуты);
  семплируем несколько кадров в окне `[сид, сид+300]`, читаем часы, решаем
  `offset = t_video − t_game` (медиана по консистентным чтениям, существующий
  `compute_offset`). Не удалось прочитать → `None`, фолбэк на ручной `--video-offset`.
- Существующая инфра (`crop_hud_clock`, `sample_clock_reads`, `compute_offset`,
  `video_time_for`, `ClockRead`) переиспользуется; `tesseract_clock_ocr` заменяется
  `read_clock` (шаблоны), tesseract-путь можно оставить как опциональный.
- Ограничение (в области): привязка к 1920×1080. Другое разрешение → масштаб шаблонов
  (не в v1; при несовпадении — фолбэк на ручной offset).

### `video/clip.py` — нарезка клипа эпизода (склейка)

```python
def clip_window(game_time, offset, before=20, after=10) -> tuple[float, float]   # (t0_video, t1_video)
def extract(video, game_time, offset, out_mp4, ffmpeg) -> None                   # H.264 720p
```

`build_clip_command` расширяем: `-ss/-to` из `clip_window`, транскод
`-c:v libx264 -crf 23 -preset veryfast -vf scale=-2:720 -an` → ~5 МБ, играет в
браузере. `-an` (без звука) — для разбора не нужен, легче.

### `report.py` — `render_match_report` (папка-отчёт)

```python
def render_match_report(match_id, episodes, cards, deep_briefs, clips, out_dir) -> None
```

- Пишет `out_dir/index.html` + `out_dir/clips/NN.mp4`.
- Хронологический список карточек: время (кнопка-якорь), вердикт, `facts`, числа,
  встроенный `<video src="clips/NN.mp4" controls>` (если клип есть).
- Для deep-эпизодов дополнительно блок брифа (переиспуз `_moment_brief_section` без
  base64-картинки — вместо неё видео карточки).
- Без клипов (нет записи/выравнивания) — тот же отчёт, карточки без `<video>`.

### CLI — `analyze`

- `--coach` при наличии реплея и (видео или авто-найденной записи) → **папка-отчёт по
  эпизодам** (`--out` трактуется как директория). Без реплея → прежний одиночный отчёт
  Ф0 (совместимость).
- Новые флаги: `--deep N` (сколько глубоких, дефолт 1, кап 2); `--video PATH` (иначе
  авто-поиск в `gamerecordings`); `--video-offset N` (иначе `auto_offset`);
  `--gamerecordings DIR` (дефолт — путь Steam userdata).
- Мягкая деградация на каждом видео-шаге: не нашли запись / не выровняли / ffmpeg упал
  → рендерим отчёт по данным без клипов, печатаем причину (как сейчас с реплеем).

## Анти-результатничество — как сохранено

- Карточки: чистый КОД поверх `info_state_at` (в `ParsedReplay`/`InfoState` исхода
  нет — только позиции, HP, вижн). Числа эпизода — дельты голды/опыта/урона (это НЕ
  исход матча; помечаются как «следствие эпизода», не итог, — как в текущем брифе).
- Глубокий разбор: **N отдельных вызовов** `explain_moment`, каждый видит ОДИН эпизод
  (тот же контракт, что сегодня). Пакетного «весь матч в одном промпте» НЕТ — иначе
  модель увидела бы дугу и могла вывести исход.
- Тест-сканер (существующий, ловит `radiant_win`/счёт/победа-поражение в LLM-входах)
  расширяется на: (а) промпты всех глубоких эпизодов, (б) текст карточек в отчёте.

## Стадии сборки (снижаем риск, каждая — живая проверка перед следующей)

- **Стадия A — эпизоды + карточки + папка-отчёт (данные-only, без видео).**
  `episodes.py`, `coach/episode_card.py`, `select_deep`, `explain_scored`,
  `render_match_report`, CLI. Работает на любом матче с реплеем; карточки без клипов.
  Проверка: прогон на 8961642706 — все ~10–15 эпизодов с фактами, 1 глубокий, исхода
  нет.
- **Стадия B — видео: локатор + сшивка + авто-выравнивание + клипы.**
  `video/steam_recording.py`, `video/align.py` (шаблоны + ассеты цифр), `video/clip.py`
  extract, встраивание `<video>` в отчёт, авто-флаги CLI. Проверка: тот же матч — клипы
  30с в карточках, авто-offset совпал с ручным 183 (±2с).

## Тестирование

- **Юниты (чистые функции, фейки):** `my_death_times` (синтетические кадры alive/dead,
  включая респавн и соло-смерть вне драк), дедуп смерть↔драка, severity, `select_deep`
  (порядок вердиктов), `clip_window` (границы, кламп ≥0), `find_session` (выбор сессии
  по окну, none при непокрытии), `read_clock` (синтетический кроп с известными цифрами),
  `render_match_report` (структура HTML, наличие/отсутствие `<video>`).
- **Анти-результат:** расширить сканер-тест на карточки и промпты всех deep-эпизодов.
- **Существующие 183 pytest — зелёные** (ничего не ломаем).
- Живые смоки — в конце каждой стадии, вручную (сеть/ffmpeg/claude -p не в CI).

## Область / вне области

**В области:** обзор всего матча по эпизодам с карточками-фактами и клипами 30с;
1–2 глубоких LLM-разбора; авто-сборка видео из записи Steam (локатор+сшивка+часы);
папка-отчёт.

**Вне области (осознанно):** combat-log урона/кастов (как и в Ф1 — отложено); объективы
(тауеры/Рошан) и покупки/варды как отдельные эпизоды (пользователь выбрал узкий набор
«где было решение»); мультиразрешение авто-выравнивания (только 1920×1080, иначе ручной
offset); связный «нарратив по всему матчу» одним LLM-вызовом (нарушил бы анти-результат);
пакетный разбор >2 эпизодов LLM.
```
