# Фаза 1 — Парсинг реплея `.dem` (позиции + полное состояние)

**Дата:** 2026-08-21. Ветка: продолжение `feat/single-match-coach` (или новая `feat/replay-parse`).

**Цель фазы:** достать из реплея то, чего нет в OpenDota-агрегатах — **позиции всех героев и полное состояние по времени** — и на их основе реконструировать **информационное состояние игрока в точке решения**, чтобы разбор Ф0 из режима «нужен ручной разбор» (`NOT_ENOUGH_INFO`) перешёл в заземлённый рид.

## Центральный принцип (согласован с пользователем)

«Как надо было» судим из того, что игрок **МОГ ЗНАТЬ** в момент решения, а не задним числом. «Как надо было» — синтез из трёх источников разной надёжности, которые в разборе разделяются явно:

1. **Выводимо из данных (сильный):** last-seen врагов, «4 героя не светились 20 сек» — факт, не мнение.
2. **Курируемый принцип (средний):** `moment_principles.md`.
3. **Параметрическое знание LLM о Доте (слабый, опасный):** всегда как гипотеза, никогда как истина.

Та же дисциплина, что уже даёт `NOT_ENOUGH_INFO`: утверждаем уверенно только то, что видно в данных.

## Находки разведочного спайка (2026-08-21, реальный матч 8944053733)

Спайк на живом реплее (`spike_replay/`, gitignored) снял ключевые неизвестности:

- **Компрессия — zstd, не bzip2.** Valve отдаёт `.dem.bz2`-URL, но тело — Zstandard (magic `28 B5 2F FD`). Распаковка: python `zstandard` (0.25.0 установлен). Распакованный `.dem` начинается с `PBDEMS2` (Source 2).
- **Парсер — `github.com/dotabuff/manta` v1.5.0** (Go 1.24.2 установлен; Java нет → JVM-Clarity отпал). Парсит текущий протокол **без ошибок за ~1.5–2.5 сек** на 38-мин матч (5.4М обновлений сущностей). 24 матча ≈ минута CPU. Объём — не проблема.
- **Схема сущности героя** (класс `CDOTA_Unit_Hero_<Name>`, 252 свойства), реальные имена полей:
  - Позиция: `CBodyComponent.m_cellX/m_cellY` (ячейка, uint) + `CBodyComponent.m_vecX/m_vecY` (смещение внутри ячейки, float). Мир = `cell*128 + vec - 16384` (ширина ячейки 128, полу-карта 16384).
  - Направление героя: `CBodyComponent.m_angRotation` = `[pitch yaw roll]` (НЕ камера — куда повёрнут перс).
  - `m_iHealth`, `m_flMana`, `m_iCurrentLevel`, `m_iCurrentXP`, `m_lifeState` (0=жив), `m_iPlayerID` (0–9=слот), `m_iTeamNum` (2=Radiant, 3=Dire), `m_vecAbilities.*` (хэндлы способностей).
- **10 героев** идентифицируются по `m_iPlayerID`. **Грабля:** иллюзии (Phantom Lancer и т.п.) — тот же класс; отделять реальных героев (по стабильному хэндлу основного юнита / флагу иллюзии).
- **Игровые часы:** `m_pGameRules.m_flGameStartTime` (время хорна) + текущий тик (30/сек) → `game_time = tick/30 - m_flGameStartTime` (как OpenDota, 0 на 0:00). `m_nGameState` (5=игра идёт), `m_bGamePaused`/`m_nTotalPausedTicks` — учёт пауз.

## Архитектура

```
.dem.bz2 (Valve, zstd) ─► [Python: download + zstd-decompress] ─► .dem
                                                                    │
                                          [Go/manta extractor] ◄────┘
                                          тупой: парсит → JSONL в stdout, НОЛЬ логики
                                                                    │
                                          [Python: кеш JSONL на диск] ◄─┘
                                                                    │
                                          [Python: ParsedReplay + аналитика]
```

**Граница жёсткая:** Go-бинарь только извлекает и печатает JSONL; вся аналитика (информационное состояние, вижн, last-seen) — в Python. При смене вопросов Go не трогаем. Распарсенное кешируется на диск как `opendota.py` кеширует матчи (`cache/replay_<match_id>.jsonl`).

**Почему бинарь, а не Go-как-сервис:** одноразовый батч-парс, простой контракт stdin/stdout; бинарь собирается один раз (`go build`), рантайм-зависимостей не тянет.

## Декомпозиция фазы (каждый срез — свой цикл спека→план→сборка)

- **1a-state** — экстрактор состояния + инфраструктура (скачивание, zstd, кеш). Позиции/HP/мана/уровень/XP/lifeState/направление всех 10 @1 Гц. **Фундамент, полностью де-рискнут спайком.** Разблокирует «где были враги в момент T».
- **1a-events** — combat log + варды (поставлен/истёк/снят + координаты) + касты. Отдельный мини-спайк формата сообщений демки (события — в demo-сообщениях, не в сущностях).
- **1b** — информационное состояние: `info_state_at(parsed, t)` → позиции всех, last-seen врагов + длительность пропажи, приблизительное покрытие вижна (радиусы от союзников+вардов, помечается как оценка), ресурсы игрока, близкие тайминги.
- **1c** — обогащение промпта Ф0 инфо-состоянием; `NOT_ENOUGH_INFO`-моменты → заземлённые риды с тремя уровнями уверенности.

Ниже детально специфицирован только **срез 1a-state** (первый цикл). Остальные срезы получают свои спеки, когда до них дойдём.

## Срез 1a-state — детальная спека

### Компонент A: Go-экстрактор (`replay_tool/`)

Отдельный Go-модуль в репозитории (собирается в бинарь `replay_tool` / `replay_tool.exe`).

**Интерфейс:** `replay_tool <path-to-.dem>` → JSONL в stdout, по одной строке на запись. Ошибки — в stderr, ненулевой код возврата.

**Контракт вывода (JSONL), два типа строк:**

```json
{"t":"meta","match_id":0,"game_start_time":123.4,"tick_rate":30,"heroes":[
  {"player_id":0,"team":2,"hero":"npc_dota_hero_phantom_lancer"}, ...]}
{"t":"state","time":845,"units":[
  {"pid":0,"x":-4210.0,"y":1980.5,"yaw":45.0,"hp":648,"max_hp":700,
   "mana":363.0,"level":6,"xp":2200,"alive":true}, ... 10 юнитов ]}
```

- `meta` — одна строка в начале: время хорна, тикрейт, состав (player_id → герой/команда).
- `state` — одна строка на **каждую игровую секунду** (`game_time` целое, 0 на хорне). Внутри — снимок 10 реальных героев (иллюзии исключены).

**Семплирование:** экстрактор держит последнее состояние каждого героя (обновляется по `OnEntity`), а по нарастанию `floor(game_time)` печатает снимок. 30 тик/сек избыточно — 1 Гц достаточно для тренерского разбора и даёт ~2000 строк на матч.

**Координаты:** `world = cell*128 + vec - 16384` по X/Y (Z не нужен). `yaw` = `m_angRotation[1]`.

**Отсев иллюзий:** реальный герой — юнит с валидным стабильным присутствием по `m_iPlayerID` без флага иллюзии (`m_bIsIllusion`/`m_hReplicatingOtherHeroModel` != invalid); финальный критерий уточняется на реализации по свойствам класса.

**Время:** `game_time = currentTick/tick_rate - m_flGameStartTime`, вычитая паузы (`m_nTotalPausedTicks`). Только строки с `game_time >= 0` (после хорна).

### Компонент B: Python-обвязка (`ingest/replay.py`)

```python
def parse_replay(match_id: int, cache_dir: Path = Path("cache")) -> ParsedReplay
```

Поток: взять `replay_url` из кеша матча (`fetch_match`) → скачать `.dem.bz2` → zstd-распаковать → прогнать `replay_tool` → распарсить JSONL → сложить в `ParsedReplay` → закешировать JSONL (`cache/replay_<id>.jsonl`). Повторный вызов читает кеш, минуя скачивание и парс.

**Модель данных** (`models.py`, новые dataclass):

```python
@dataclass(frozen=True)
class UnitState:
    pid: int; x: float; y: float; yaw: float
    hp: int; max_hp: int; mana: float; level: int; xp: int; alive: bool

@dataclass(frozen=True)
class ReplayFrame:
    time: int                    # game_time, сек, 0 на хорне
    units: dict[int, UnitState]  # pid -> состояние

@dataclass(frozen=True)
class ParsedReplay:
    match_id: int
    game_start_time: float
    heroes: dict[int, str]       # pid -> npc_dota_hero_*
    frames: list[ReplayFrame]    # по секунде

    def frame_at(self, t: int) -> ReplayFrame | None   # ближайший кадр <= t
```

### Обработка ошибок

- Реплей недоступен (Valve удалил, HTTP != 200) → `ReplayUnavailable`, `analyze` продолжает БЕЗ реплей-слоя (как сейчас без `--video`). Реплей — обогащение, не обязательное условие.
- `replay_tool` упал/не собран/протокол не распознан → лог + `ReplayUnavailable`, отчёт по OpenDota-данным всё равно рендерится.
- zstd-распаковка упала → та же деградация.

Реплей-слой строго опционален: никакой сбой парсинга не должен ронять существующий разбор.

### Тестирование

- **Go-экстрактор:** оффлайн-проверка на зафиксированном `.dem` в спайке (не в CI — как сетевой путь `opendota.py`): визуально валидируем meta (10 героев, разумный `game_start_time`), число кадров ≈ длительность, координаты в пределах карты (|x|,|y| < 16384), монотонность времени.
- **Python-обвязка:** юнит-тесты на распарсенном JSONL-фикстуре (маленький рукотворный JSONL) → `ParsedReplay`, `frame_at`, кеш-хит/мисс, деградация при `ReplayUnavailable`. Сетевой путь (скачивание/бинарь) без юнит-тестов, инъекция раннера как у `ClaudeCliLLM`.
- **Живой смок:** `parse_replay(8944053733)` end-to-end → глазами проверить кадры и позиции на реальном матче.

## Глобальные ограничения

- Реплей-слой **строго опционален**: сбой не ломает `analyze`/`leaks`/`coach`.
- Go = тупой экстрактор, аналитика в Python (граница не размывается).
- Кеш на диске как у `opendota.py`; `cache/` уже в `.gitignore`.
- Русский интерфейс сохраняется в пользовательских строках.
- Спайк-артефакты (`spike_replay/`, ~150 МБ) — в `.gitignore`, в репозиторий не попадают.

## Вне области (сознательно)

- **События** (combat log, варды, касты) — срез 1a-events, отдельный спайк.
- **Информационное состояние и вижн** — срез 1b.
- **Интеграция в разбор** — срез 1c.
- **Ярус 3** (крипы, лейн-эквилибриум, курьер) — отложен; к «как надо было» почти не добавляет, даёт объём.
- **Камера / куда игрок смотрел** — этого в реплее НЕТ; дыра закрывается только Ф2 (CV по записи).
- **Точный туман войны по рельефу/деревьям** — в 1b считаем приближением по радиусам, помечаем как оценку.
