# План покупки: явная цель, условия и история редакций

Дата: **7 октября 2026 года**. Закончен сквозной исследовательский поток. Полное ТЗ и качество игровых рекомендаций этим этапом не аттестованы.

## Что работает

В реальном отчёте раздел «Контекстный план покупки» позволяет выбрать эпизод, сформулировать цель следующего матча или ретроспективный вопрос, указать собственное наблюдение угрозы и до шести предметов из сохранённого каталога Valve. Цель, описание, золото и подтверждение изначально пусты; неизвестные слот, доставка и остаточная цена не заполняются догадками. Подробные описания доступны только для предметов, действительно загруженных в данный snapshot; в локальном корпусе таких предметов четыре. Параметры `%...%` в исходном описании не заменяются вымышленными числами.

`learning/build_planner.py` проецирует собственные предшествующие записи и журнал покупок строго до выбранного якоря. Активация — якорь просмотра, а не восстановленный момент выбора покупки. Source context связан с match/account/actor/resource slot, dataset kind, hero/provider patch и catalog snapshot; полные послематчевые хеши, outcomes, скрытые враги и будущие покупки в аналитическую идентичность не входят. Неизвестный clock или некорректная привязка отменяют привязку эпизода. Полные source receipts остаются в исходном отчёте для проверки целостности.

`create_build_plan` сохраняет отдельный versioned declaration receipt. Текущее сообщение не становится Fact, ThreatEvidence, прошлым намерением или подтверждением исторического патча. Указанные `available_gold` и `remaining_costs` дают только арифметику бюджета; полная цена живого каталога не заменяет остаточную цену с компонентами. Свободный слот и доступ к покупке даже при ответе «да» остаются непроверенными сведениями. Разница расходов не ранжирует полезность.

Каждый предмет получает условие цели, вопросы об эффекте, затраты, ограничения, условие пересмотра и ссылки Valve. Есть условная возможность отложить выбор; она не объявляется гарантированно выполнимой или лучшей. Итог имеет `research_assistance`, `feasibility=unknown`, `patch_applicability=not_established`, `optimality=not_established`, `training_eligible=False`. Нет win%, оценки ущерба или автоматического назначения упражнения.

## Сохранение и API

Loopback backend принимает `POST /api/build-plan` с envelope `{job_id, request}`. Request требует schema `foresight.build-plan-request.v1`, decision ID, текущий `source_context_hash`, goal kind/description и `confirmed=True`. Snapshot берётся из конфигурации сервера; клиент не может подменить каталог. Проверки Host/token, размера, чисел и неизвестных keys действуют также здесь.

Сохранение добавляет UTC `recorded_at` и пересчитывает полный payload hash. `build-plan-history.jsonl` содержит неизменённые редакции; следующий запрос требует точный предыдущий plan ID, payload integrity и совпадение исходной личности/каталога. Переход между якорями того же игрока разрешён как **сопоставление сценариев**, не как прогресс поведения. Конкурирующий или устаревший запрос отклоняется до записи. `GET /api/build-plan/{job_id}` возвращает последнюю редакцию текущей серверной сессии. После перезапуска сервера предыдущие файлы сохраняются, но сессионные jobs и их API не восстанавливаются автоматически.

Обновление страницы восстанавливает результат, сохраняя новую цель пустой и подтверждение выключенным. Есть экспорт текущего JSON; история доступна как артефакт отчёта. Offline HTML показывает форму и объяснение недоступности server calculation. Несовместимые legacy anchors остаются видимыми в отчёте, но не получают пригодной привязки для нового плана.

## Проверка

Добавлены **47 planner tests**, **11 UI tests**, четыре сквозных HTTP tests и регрессии аналитической идентичности покупок. Общий Python suite: **722 passed**, Go source на этом этапе не менялся; ранее прошли **9 tests**, module verification и build. Актуальные результаты архива и чистой установки wheel — `out/verification/release-readiness.json`.

Независимый инженерный аудит использовал реальный match **9030822324** и сохранённый каталог: для BKB полная цена 4050 не подставлялась вместо заявленного остатка 900; заявленное золото 2000 давало остаток 1100 с unknown feasibility. Outcome/full-source-receipt mutations не меняли префикс; неверный source context отклонялся. Это проверка алгоритмических контрактов, не экспертная аттестация механики игры.

Browser QA создала явно подписанный тестовый сценарий Ghost/BKB, проверила отказ без подтверждения, обе редакции, смену эпизода, unknown при пустой остаточной цене, восстановление последнего результата после полной загрузки и пустую новую цель. Проверены desktop 1440 и mobile 390, отсутствие горизонтального overflow, broken anchors и console errors. QA записи не являются личной целью, экспертными labels или наблюдением пользы пользователя.

## Что остаётся

Историческая механика, pre-choice POV, действительная доступность покупки/применения, opponent item visibility, конкретная team task, verified contextual rule registry и независимая проверка полезности пока не установлены. Тип угрозы из формы не даёт подтверждённого «предмет против угрозы». Полный opportunity census, клиентная сверка visibility/control и реальные экспертные labels также остаются открытыми. Нынешний поток закрывает ввод, условное сравнение и пересмотр плана; он не закрывает требования проверенного индивидуального билда или полного тренера.
