# Завершение доступного этапа аналитики — 7 октября 2026

Этот документ фиксирует предыдущий этап с 850 тестами. Следующее исполнение и актуальная проверка: [choice/knowledge/ward stage](2026-10-07-choice-knowledge-ward-stage.md); часть названных ниже недостающих conditional алгоритмов теперь реализована, а требования реальной валидации сохраняются.

Это исполнение последующих разрывов исходного ТЗ, включая код, реальный replay, независимый инженерный review и переносимую поставку. Полное ТЗ игрового тренера остаётся открытым: реализация исследовательских инструментов не устанавливает качество оценки игры. Пункт 12 исходного задания разрешает закончить максимально полный доступный этап и перечислить недостающие внешние входы; ниже они названы отдельно от оставшихся алгоритмов.

## Реализованный сквозной результат

- TP/smoke: отдельные последовательности каждого источника складываются в интервалы apply/remove по точному имени цели и признаку иллюзии. Использования предмета остаются отдельными событиями. Незавершённые, повторные и неоднозначные интервалы сохраняются. Удаление modifier не объявляет прибытие, прерывание, раскрытие smoke или истечение длительности. Имена не устанавливают entity generation.
- Префикс: в историю входят только записи выбранного источника строго до cutoff. Поля и вложенные details проходят allowlist; будущие записи и metadata полного матча не влияют на результат или его hash. Provider objectives остаются ретроспективой и не импортируются в replay prefix.
- Наблюдения инвентаря: обходятся все supplied timing samples, включая срезы без нажатия. Проверяются replay/trace identity, выбранный SteamID, hero/resource slot, точные handles/generations и references полей. Соседние совпадающие сырьевые сигнатуры образуют наблюдаемые окна. Пустой компактный inventory не доказывает отсутствие предмета; sampling coverage не означает полный учёт игровых возможностей.
- Задача варда: собственная командная постановка выбирается из original callback provenance. Текущая явно подтверждённая цель, предполагаемая альтернатива и шесть вопросов проверки сохраняются отдельно от прошлой цели игрока. Предшествующие объекты вычисляются до callback постановки по entity/generation. Позднее время и позднее удаление не подставляются назад. При неизвестной команде, владельце, видимости или времени вывод остаётся неизвестным.
- Карта позволяет выбрать постановку мышью или клавиатурой. Форма поддерживает сохранение, изменение цели/постановки, SHA-chain редакций, восстановление результата после reload и скачивание JSON. Новая цель и подтверждение после reload остаются пустыми. История находится в `ward-plan-history.jsonl` соответствующей локальной задачи. После перезапуска сервера старые сессионные jobs не восстанавливаются.
- Проверка фактов отклоняет чужой input/replay/patch, неверную цепочку revisions и дублирование annotations до подсчёта качества. Совпадение decision ID не заменяет привязку к конкретному входу.

Модули: `ingest/semantic_lifecycle.py`, `decisions/opportunity_discovery.py`, `learning/ward_plan.py`, `learning/ward_plan_surface.py`; интеграция в `live_report.py`, `semantic_surface.py`, `server.py` и `wards.py`.

## Ошибочные предположения, найденные review

`m_fCooldown` раньше сравнивался с абсолютным engine time. В реальном trace положительные значения убывают как остаточная длительность; без проверки wire semantics обе интерпретации остаются гипотезами. Теперь сохраняются raw operand, references и обе гипотезы, но readiness всегда unknown. Старые cached flags демотируются в resource review, discovery и build planner. Совпадение двух гипотез также не является проверкой готовности.

Полный реальный trace повторно прочитан: 5 prefixes, 2999 timeline samples; 48 inventory cooldown checks остаются unknown. Discovery совпал с нормализованным сохранённым источником. В 402 samples две трактовки дают разные результаты; это конкретное свидетельство недопустимости прежнего автоматического grant. Нормализация не меняет raw values/references; исходный cached artifact сохранён отдельно в локальном `out`.

Также исправлены утечка metadata через semantic prefix, импорт будущей source-domain классификации, недостаточная identity-проверка fact-quality, подмена declaration receipt в ward revision и HTML escaping неизвестных handles. Будущие записи, совпадающие имена иллюзий, неизвестные clocks, generation reuse и stale/foreign requests проверяются регрессионными тестами.

## Фактическая проверка

Публичный матч `9030822324`, выбранный аккаунт `904131336`, Kez: 5 защитных активаций, 2999 inventory samples, 262 callback события вардов. Получены 7 сырьевых inventory windows; они не объявлены пригодными моментами выбора. Из combat-names получены 147 TP/smoke интервалов: 82 TP, 65 smoke; 146 paired, 1 left-censored, 1 ambiguity. Источники не дедуплицируются по близкому времени.

Для команды выбранного аккаунта доступно 69 постановок. Первая имеет неизвестное prefix time, хотя более поздний clock существует: поздние сведения назад не переносятся. Кто поставил вард и что увидел игрок, не установлено.

Полная локальная suite: **850 Python tests**, **9 Go tests**, Go module verification/build. Browser QA проверяет реальный отчёт, пустой ввод, отказ без подтверждения, неизвестное время, сохранение и пересмотр ward plan, reload, выбор на карте, desktop/mobile и отсутствие ошибок JS. Явно помеченные QA declarations не являются целями пользователя, expert labels или историей поведения.

Свежие wheel/sdist проходят аудит содержимого и установку в новый temporary venv вне checkout, без PYTHONPATH/PYTHONHOME. Точные архивные SHA, JUnit и итог smoke сохраняются в `out/verification/release-readiness.json`. GitHub CI подготовлен для Windows/Linux; запуск на GitHub и Linux здесь не выполнен. В `out/release-build` не входят replay, локальные runtimes и пользовательские данные.

## Что остаётся открытым

**Внешние входы:** независимая сверка клиентом/POV, истинное соответствие game build↔patch↔механики, два реальных независимых reviewer, запечатанная проверочная выборка и настоящие baseline/followup пользователя. Реальных expert labels и проверенных игровых вердиктов сейчас 0. Поля accepted/verified в импортируемом JSON не заменяют эту работу.

**Алгоритмы после проверки источников:** реальный cue/choice/deadline resolver и полный census пригодных возможностей; command/target/control feasibility; temporal knowledge/visibility/staleness; TP arrival/interruption и smoke-break causes; temporal objective/map state с исторической геометрией; проверенная рубрика одного item/threat criterion; полезность/безопасность/дублирование ward vision и доступные альтернативы; admission подтверждённых привычек и советов по validated критерию. Эти функции нельзя считать реализованными лишь потому, что UI умеет показать unknown.

Первый следующий проверяемый результат: одна исторически подтверждённая пара предмет/угроза на одном патче, клиентно проверенные собственные и доступные игроку сведения, независимая разметка assessability/качества на смешанных исходах и последующий тест совета пользователем. Формат необходимых входов: [пакет внешнего допуска](2026-10-07-external-validation-inputs.md).

## Запуск

В подготовленной папке: `python scripts/real_workbench.py`, открыть `http://127.0.0.1:8765/`, выбрать игрока и создать отчёт. Разделы «Интервалы TP и smoke», «Наблюдения без отбора по активациям» и «Задача варда» показывают текущий этап. Статическая версия: `out/real-review/index.html`; запись плана требует локального сервера. На чистой машине следовать `INSTALL.md` и предоставить собственные входы — локальный corpus в поставку не включён.
