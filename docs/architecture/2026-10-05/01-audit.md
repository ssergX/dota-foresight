# Аудит локального снимка

Ссылки на строки ниже относятся к исходникам, прочитанным 5 октября 2026. «Есть код» означает наличие реализации, а не подтверждённую корректность на реальном replay. Аудит не проверяет текущие внешние API, механику актуального патча или содержимое GitHub.

## Проверка восьми предположений из задания

## Дополнительные риски

**P0 — будущее меняет прошлую видимость.** `_obs_wards_active_at` (`coach/info_state.py:128–143`) обходит все события и хранит placement/removal по одному `id`. Повторное использование индекса сущности в будущем перезаписывает прошлый жизненный цикл. В синтетическом воспроизведении видимость врага на t=10 меняется True→False после добавления placement только на t=30. Решение: entity generation и fold только разрешённого префикса; тест prefix invariance обязателен.

**P0 — итоги драки маркированы началом.** `events.py:22–29` кладёт суммарные deaths, damage и gold delta в событие на `tf.start`; `coach/moment_prompt.py:30,45` сериализует `event.data` целиком. Запрет одного поля `radiant_win` это не обнаруживает. Даже надпись «следствие эпизода» не предотвращает влияние на оценку, если оно уже передано оценщику.

**P0 — подсказки самого промпта допускают hindsight.** `coach/episode_note.py:31–33` разрешает учитывать скрытые позиции и советовать «стоило заподозрить/проверить». Короткий промпт не передаёт вердикт детектора, а parse_note проверяет практически только форму. Гипотетический тон не делает недоступный факт допустимым доказательством.

**P1 — отсутствующее состояние превращается в ноль.** `replay_tool/main.go:174–188` игнорирует успешность ряда property reads. `coach/info_state.py:182–184,218–224` для отсутствующего героя формирует нулевые координаты/HP и `alive=False`. Это создаёт вымышленные факты, а не мягкую деградацию. Часть nullable OpenDota-полей уже сделана правильно; эту практику нужно расширить, а не отвергать весь ingest.

**P1 — stale и never-seen смешаны с настоящим знанием.** `ParsedReplay.frame_at` возвращает любой предыдущий кадр без предела устаревания; `info_state.py:195–196` сравнивает `seen == t`. Кадр t=10 даёт visible=True на t=10 и False на t=11 без нового наблюдения. Никогда не виденный враг получает duration от игрового нуля. Нужны время измерения, срок пригодности и состояние `never_observed`, а не выдуманная точная длительность пропажи.

**P1 — идентичность и время не имеют достаточного контракта.** Slot, entity index и герой не равнозначны; фильтрация иллюзий по признаку в Go — полезная попытка, но не доказательство корректности clones/подконтрольных сущностей/смены сущности. Python приводит frame time к int, а parser/schema/patch не входят в cache key (`ingest/replay.py:40,86–89`). Повторный анализ после смены парсера может читать прежний артефакт.

**P1 — знаменатель бенчмарка завышен.** Registry проверяет наличие любого `benchmarks`, `median_pct` берёт только требуемый metric, а `make_leak` записывает `sample_size=len(rows)` и HIGH. В пяти строках может быть лишь одна релевантная метрика. Частота/достоверность должны рассчитываться по фактическим значениям конкретного признака.

**P1 — история не задаёт сопоставимые периоды.** `coach/progress.py:32–35` ищет key без роли; `CoachBrief` не хранит отдельный focus_role, compare_focus не проверяет совпадающие match_id и версии. `tests/test_coach_orchestrator.py` допускает повторный анализ тех же матчей как прогресс. Нужен baseline с составом выборки и замороженной политикой измерения.

**P1 — нормативные ошибки находятся и в базе знаний.** `coach/principles.md` связывает отсутствие прироста золота с отсутствием цели, низкий урон с отсутствием импакта, короткую жизнь варда с бесполезностью. Это недоказанные обобщения; исправления одних детекторов недостаточно. Механические советы без patch-scoped источников также не считать проверенными. Перевести базу в условные criteria/hypotheses с исключениями.

**P1 — факты карточки не видны пользователю.** `_episode_card_html` (`report.py:156–181`) отображает вердикт, LLM insight и клип, но не `card.facts`/`numbers`. Наличие фактов в Python DTO не означает проверяемость вывода в UI.

**P2 — selection bias и потеря идентичности.** Список эпизодов формируется вокруг драк/смертей/просадок; хорошие решения без этих исходов почти не представлены. Разные решения в одной секунде могут столкнуться в словарях notes/deep_briefs по `game_time` (`coach/match_review.py`). Дедуп относительно драки не доказывает, что это один выбор. Нужны episode_id, decision_id и явная связь нескольких решений с одним incident.

## Сохранить / заменить / пока отсутствует

| Компонент | Реально есть | Что сохраняем / меняем |
|---|---|---|
| Python + Go manta | Экстрактор, JSONL ingest, dataclasses | Сохраняем стек, версионируем контракт, вводим доказанные capabilities |
| OpenDota | Fetch/normalize, матчи/события/перцентили | Адаптер оставить; значения провайдера требуют семантической проверки. В частности имя `gold_t` само не доказывает net worth |
| Replay | Позиции, HP/mana/level/xp/alive, wards | Это извлекаемые поля, не аттестация точности; предметов/casts/control/full observability в контракте нет |
| Эпизоды и scoring | Детерминированный discovery/ranking | Сохранить как индекс инцидентов; отделить от evaluator |
| Video | Поиск Steam-записи, выравнивание, нарезка | Сохранить; добавить качество и ошибку синхронизации; видео опционально |
| LLM | Provider protocol, fake, cache | Сохранить транспорт; изменить вход на проверенные claims, cache scope, валидацию вывода |
| Leaks/history | Registry, role filtering, snapshots | Сохранить организацию; заменить семантику ошибок и прогресса |
| UI | Генератор статического HTML | Развивать постепенно; сначала доказательства/отказы, затем карта/таймлайн |
| Сходные решения | Нет самостоятельного evidence-backed retrieval | Новый модуль после первого evaluator, не переименованный percentile |
| Контекстные билды, проверенные учебные матчи | Полноценных механизмов не найдено | Явный unavailable до подключения источников и механик |
| Интерактивная карта вардов и feedback | Есть ward events, полноценного сценария нет | Новые представления поверх общих контрактов, без фиктивных интеграций |
| Независимый экспертный benchmark | Не найден | Обязателен перед заявлениями о качестве |

## Проверка и её пределы

Прочитаны исходники, релевантные тесты и прежняя спецификация обзора матча. Восемь подозрений из задания подтверждены на уровне кода; дополнительные поведения воспроизводятся `audit_probes.py`. Доступный Python не содержит pytest; полный тестовый набор не выполнен. Нет оснований повторять README «218 тестов зелёные» как результат этого аудита. Синтетические проверки не проверяют manta, клиент Dota, точность видимости или полезность совета.
