# Текущая архитектура и передача Foresight

Дата: 9 октября 2026. Этот документ — актуальная точка входа исполнителя и reviewer. Пакет `2026-10-05` сохраняется как исходный аудит; его S0–S2 и формулировка «нового приложения нет» больше не являются текущим заданием.

## Что принимается

Поручение архитектору: архитектура аналитики, оценка решений, поиск ошибочных предположений и конкретная передача реализации. Все четыре результата представлены исходниками, контрактами, независимыми инженерными проверками и этой передачей. Первый доступный инженерный этап §12 завершён после финальных проверок, записанных в release-readiness. Основной критерий полезности и игровой точности требует внешней приёмки и не объявляется достигнутым.

Исходное ТЗ требует ограниченный первый класс (§5), запрещает одновременную реализацию всех функций (§12) и допускает инфраструктуру с явными непроверенными утверждениями при отсутствии внешних данных (§11–12). Требования полного продукта сохранены в [единой матрице](../implementation/2026-10-08-tz-closure.md). Их нельзя закрыть флагом validated, зелёными synthetic tests или публикацией GitHub.

## Исполняемая архитектура

Go/Manta пишет raw deltas и callback sources. Python проверяет manifest/digests, lifetime/generation, source scope и exact prefix. Полные world/outcome artifacts остаются отдельно. Единица оценки — доступная возможность выбора, а не смерть, GPM или популярность действия.

| Граница | Действующий код | Контракт |
|---|---|---|
| Источник и идентичность | `ingest/trace.py`, `command_binding.py`, `unit_control.py`, `projectile_source.py` | Replay/build/account/handle/generation и source-local ordinal; raw association не доказывает agency или стадии команды. |
| Знание и время | `evidence/knowledge.py`, `temporal.py`, `clock_math.py` | World, team, screen и intent разделены. Bounds decimal-exact; unknown/foreign clocks, undelivered values и future facts не создают support. |
| Возможность и действие | `decisions/choice_window.py`, `choice_monitor.py`, `mechanics_adapter.py`, `command_census.py` | Feasible/infeasible/unknown; census и continuous coverage отдельны от snapshot. Исчезнувший operand и unresolved transition закрывают допуск. |
| Альтернативы | `ingest/impact_prefix.py`, `decisions/defensive_impact.py`, `movement.py`, `terrain.py` | Исполняются только supplied finite model, explicit goal и разрешённый prefix. Model bounds не становятся общим тактическим пониманием. |
| Критерий и отзыв | `validation/criterion_gate.py`, `decisions/impact_pipeline.py`, `analytical_workflow.py` | Current exact registry/release/case witnesses, mixed holdout, revocation. JSON snapshots не экспортируют полномочия review. |
| Персональная история | `learning/verified_history.py`, `training.py`, `study.py` | Full opportunity manifest, examples/counterexamples, сопоставимые периоды, explicit exercise и measured features. Отзыв case/source отзывает текущую историю. |
| Пользователь | `live_report.py`, `analytics_surface.py`, `server.py`, `surface.py` | Источники, альтернативы, отдельный outcome и unknown; feedback — предложение для review. Видео служит навигации и не подтверждает POV/часы. |

### Принятые решения и отвергнутые предположения

Сохраняются Python, Go, CLI и локальный HTML. Нет архитектурного основания переписывать проект или вводить распределённый inference ради первого класса. Детерминированная оценка работает без LLM, видео и сети при имеющихся артефактах.

Смерть, survival, ready BKB, урон, ward count и редкость действия не задают verdict. Raw control mask не означает возможность применить предмет; source command не означает attempted/accepted/committed. Ноль полученных labels не означает отсутствие ошибок. Два одинаковых unknown context не устанавливают сравнимость. Целый artifact hash нужен admission, но не разрешается как семантический признак prefix. Полезность совета и изменение поведения проверяются отдельно от extraction и correctness.

Точные численные границы округляются консервативно при JSON export. Недоступные operands не участвуют даже в candidate arithmetic. Доставка cue и его noticing различны. Будущий truth value, sample или metadata не меняют текущий verdict, reasons или semantic hash. За этими решениями стоят regression/metamorphic tests, а не только текстовые инструкции.

## Следующее конечное задание Sol

Не реализовывать повторно S0–S2, generic history/coaching, graph solver, typed command-stage bridge или criterion gate. Они уже есть. Не добавлять новые карточки, чтобы маскировать отсутствие игрового критерия.

Выполнить S3: проверить пригодность одной исторической пары item/threat для `defensive_activation.v1` на доступном replay9030822324/account904131336, начиная с BKB и одного independently установленного incoming threat. Provider patch60/raw build6943 — исходные значения, а не аутентифицированный historical mechanics mapping.

1. Проверить extraction/account/source receipts на выбранном интервале. Найти клиентно проверяемый anchor и controller/ownership. 1314 own raw linked references, 38 BKB references и 5 effects имеют разный смысл; их нельзя вычитать для получения ошибок.
2. Связать clock/pause/event ordering и delivery с конкретными raw records. Без такой связи решение не получает точного reaction window. Supplied video offset остаётся пользовательской навигацией.
3. Для одной пары установить historical class/item/threat rules и exceptions: costs, cooldown representation, control/channel/target restrictions, actual action stage и prior observable cue. Raw world projectile не подтверждает screen signal.
4. Передать эти источники действующим prefix/case APIs. Реальные point receipts требуют отдельной extraction и blinded decision проверки; новые источники должны отозвать старые exact admissions.
5. Проверить activate/hold с prior goal и unknowns на всех подходящих случаях выбранного интервала, включая non-use и отсутствие смерти. Denominator берётся из проверенного census, а не из 5 effects.
6. Закончить одним из результатов: admit within explicit scope; reject candidate pair с основанием; remain data-blocked с точными недостающими полями/receipts. Не менять scope после просмотра ошибки без новой версии задания.

Входы, которые здесь не созданы: клиент/POV выбранной версии, историческая механика и identity/build mapping, независимые люди и зафиксированные extraction/decision labels, sealed player/match holdout. В [data-spike](../data-spike/defensive-activation-v1.md) уже предусмотрен отрицательный или data-blocked итог; его нельзя скрывать написанием новой условной модели.

## Проверка Astro перед принятием

Astro проверяет: (а) что реально интерпретирует новый adapter; (б) точные sources/versions/unknown; (в) hidden/future mutation invariance; (г) action agency и census completeness; (д) good/bad outcomes вне input; (е) explanation claims в пределах criterion; (ж) отзыв source/review/release; (з) исключение synthetic и повторов из real holdout/истории. Проверку механики и качества выполняют independently от автора изменений.

Обязательная передача: изменённые файлы, команды и реальные результаты тестов, один воспроизводимый source interval, supported/unsupported capabilities, текущие open gates. Один инженерный reviewer не становится игровым экспертом из-за зелёного test suite.

## Запуск и проверка готового этапа

Чистая установка: [INSTALL.md](../../INSTALL.md). Локальная рабочая папка: `python scripts/real_workbench.py`, затем открыть `http://127.0.0.1:8765/`. Создать отчёт для выбранного аккаунта. Offline вариант: `out/real-review/index.html`. CLI с подготовленными файлами: `trace-review`, `commands-source`, `command-stages-source`, `mechanics-source`, `choice-review`, `impact-prefix-review`, `case-review`, `verified-history-review`; точные аргументы показывает `--help`.

Предоставленную локальную запись можно подключить при запуске: `python scripts/real_workbench.py --video "C:/records/match.mp4" --video-offset 123.4`. Число — пример явно заданного смещения: video seconds = source game seconds + offset. Если есть паузы/неточная синхронизация, навигация остаётся приблизительной; offset не используется как подтверждение evidence clock. CLI `trace-review` и `serve` принимают те же video options и optional `--ffmpeg`. Без записи карточка показывает недоступность; ошибки, неизвестное время, выход события за запись и отсутствие декодируемого кадра не маскируются успешным клипом. Оригинал не публикуется: report содержит только ограниченные MP4 clips и manifest с hashes.

Проверки: `python scripts/check_project.py --go PATH_TO_GO`, затем build wheel/sdist, `scripts/check_package.py`, `scripts/check_installed.py`. Актуальные результаты, SHA, установка вне checkout и source byte matches — `out/verification/release-readiness.json`. Raw replay/видео/локальные runtimes не входят в source archive. Наличие тестов Windows/Linux в CI не означает, что внешний GitHub run уже выполнен.

В этой папке нет собственного Git checkout. Внешняя родительская Git область не использовалась. После переноса исходников работать в отдельной `codex/` ветке своего checkout; публикация, экспертная приёмка и обучение не выполняются автоматически.
